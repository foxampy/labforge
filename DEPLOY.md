# Деплой сайта Livada Center

Сайт собирается и работает на **двух площадках** из одного репозитория:

1. **Vercel** — обычный режим Next.js (Node SSR), форма заявки уходит через API-роут
   `src/app/api/lead/route.ts`.
2. **cPanel / Apache** (shared-хостинг без постоянного Node) — статический экспорт
   (`output: 'export'`) + обработчик формы на PHP (`cpanel/lead.php`).

Заявки в обоих случаях отправляются в один и тот же Telegram-чат.

> ⚠️ **Безопасность.** Токен бота (`TELEGRAM_BOT_TOKEN`) и `TELEGRAM_CHAT_ID`
> **нельзя коммитить в репозиторий**. На Vercel задавайте их в переменных
> окружения, на cPanel — через переменные окружения или вручную в `lead.php`
> (этот файл с реальным токеном в git не пушим).

---

## 1. Vercel (Node SSR) — текущий режим

1. Подключите репозиторий к Vercel (Add New → Project → Import).
2. Framework Preset определится автоматически как **Next.js**, команда сборки
   по умолчанию — `next build`. Менять ничего не нужно.
3. В **Settings → Environment Variables** добавьте:

   | Переменная            | Значение                          |
   |-----------------------|-----------------------------------|
   | `TELEGRAM_BOT_TOKEN`  | токен вашего бота (из @BotFather) |
   | `TELEGRAM_CHAT_ID`    | id чата/канала для заявок         |

4. Задеплойте. Форма отправляет `POST /api/lead`, роут шлёт сообщение в Telegram.

Переменную `BUILD_TARGET` на Vercel **не задавайте** — без неё конфиг работает
в обычном режиме (с кэш-заголовками `headers()`), ровно как раньше.

---

## 2. cPanel / Apache — статический экспорт + PHP

### Шаг 1. Собрать статику локально

```bash
npm install      # один раз, если ещё не ставили зависимости
npm run build:static
```

Скрипт `scripts/build-static.mjs`:

- временно убирает `src/app/api` (force-dynamic роут несовместим с экспортом)
  и **гарантированно возвращает его на место** после сборки;
- запускает `next build` с `BUILD_TARGET=static` и
  `NEXT_PUBLIC_LEAD_ENDPOINT=/lead.php`;
- копирует `cpanel/lead.php` и `cpanel/.htaccess` в каталог `out/`.

Результат — готовый к загрузке каталог **`out/`** с `index.html`, статикой,
`lead.php` и `.htaccess`.

### Шаг 2. Загрузить на хостинг

Загрузите **СОДЕРЖИМОЕ** каталога `out/` (а не сам каталог) в `public_html`
вашего домена. Через File Manager в cPanel удобно залить `out/` как ZIP и
распаковать, либо использовать FTP.

Убедитесь, что `.htaccess` и `lead.php` оказались в корне `public_html`
(File Manager по умолчанию скрывает файлы, начинающиеся с точки — включите
«Show Hidden Files»).

### Шаг 3. Прописать токен и chat_id

Есть два способа — выберите тот, что поддерживает ваш хостинг.

**Вариант A — переменные окружения (предпочтительно).**
Если хостинг позволяет, добавьте в `.htaccess` (или в панели cPanel):

```apache
SetEnv TELEGRAM_BOT_TOKEN ваш_токен_бота
SetEnv TELEGRAM_CHAT_ID ваш_chat_id
```

`lead.php` читает их через `getenv()`.

**Вариант B — прямо в `lead.php`.**
Если `SetEnv` недоступен, откройте `lead.php` в File Manager и впишите значения
в константы вверху файла:

```php
const TELEGRAM_BOT_TOKEN_FALLBACK = '123456789:AA...';
const TELEGRAM_CHAT_ID_FALLBACK   = '-1001234567890';
```

Этот файл с реальным токеном **не возвращайте в git**.

### Шаг 4. Проверить PHP cURL

`lead.php` отправляет запрос в Telegram через расширение **cURL**. Оно должно
быть включено (на большинстве cPanel-хостингов включено по умолчанию).
Проверить можно так: создайте временный файл `phpinfo.php` с содержимым
`<?php phpinfo();`, откройте его в браузере, найдите секцию **curl** →
«cURL support: enabled». После проверки удалите `phpinfo.php`.

Также убедитесь, что у хостинга нет блокировки исходящих HTTPS-запросов к
`api.telegram.org` (иногда требуется обращение в поддержку).

### Шаг 5. Проверить форму

Откройте сайт, заполните форму заявки и отправьте. При успехе:

- браузер получит `{"ok":true}` от `/lead.php`;
- в Telegram придёт сообщение «🚗 Новая заявка — Livada Center».

Если приходит ошибка — смотрите лог ошибок PHP в cPanel (Metrics → Errors)
или включите вывод ошибок временно.
